# v0.7 — Local evidence dashboard

Generate a lightweight, mobile-friendly HTML snapshot of the existing local evidence, without a hosted application, tracking, or new subscriptions.

## Quick start

Run an offline queue job:

```bash
python -m src.compound_intelligence.scheduler enqueue --id dashboard-demo
python -m src.compound_intelligence.scheduler tick
python -m src.compound_intelligence.dashboard \
  --queue-db local-data/v06/queue.sqlite3 \
  --output local-data/dashboard.html
```

Open `local-data/dashboard.html` in your browser. It shows queue totals, completed/failed jobs, attempted evaluations and per-model exact-match metrics. No server is needed. For previously run challenge experiments, additionally pass an existing `--challenge-db local-data/v04/challenges.sqlite3` (or the relevant v0.5 workspace).

**Source selection is explicit.** The dashboard never scans unknown directories or fetches remote records. SQLite input files are opened in read-only mode, and it refuses more than 1,000 records per input. HTML escapes all evidence-derived text and has a Content Security Policy disabling scripts and network loading.

## What the dashboard does *not* do

- It does not run jobs, start autonomous agents, issue commands or update evidence.
- It is a point-in-time file; regenerate the file to see newer data.
- Scores do not measure generalized AI capability or causal learning progress.
- v0.6's bundled benchmark results are simulated, and challenge records from v0.4/v0.5 do not prove which provider generated them. Those rows are labeled `UNKNOWN_PROVIDER`.
- Passing both a queue DB and challenge DB containing overlapping experiments may double-count: the dashboard labels evidence sources, rather than claiming a global deduplicated ledger.
- HTML snapshots should be handled as local reports. Do not publish private input data or generated reports containing sensitive identifiers.

Future: signed provenance, explicitly scoped run snapshots, real model metadata, trend comparisons across distinct datasets, optional developer UI filters and local-only live refresh under opt-in controls.
