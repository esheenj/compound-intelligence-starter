# v0.6 — Bounded local queue and restart recovery

This release adds a **manually ticked** SQLite job queue, not a continuously running agent or a daemon.

## Try it

```bash
python -m src.compound_intelligence.scheduler enqueue --id first-demo
python -m src.compound_intelligence.scheduler tick --max-jobs 1
python -m src.compound_intelligence.scheduler status
python -m src.compound_intelligence.scheduler tick
```

A successful job runs the existing offline, simulated capability benchmark and stores its report in SQLite. Repeating `tick` with an empty queue does nothing. Multiple jobs can be processed in bounded batches of up to five. A separate, explicitly configured cron/service timer may call `tick`; **none is installed by this repository**.

## Safety and resilience

- **Permission boundary:** `fixture_benchmark` is currently the *only* admissible capability. There is no shell, code execution, internet retrieval, exchange order, system administration, or arbitrary Python import action.
- **Finite operation:** one tick processes at most five jobs and returns, rather than looping indefinitely.
- **Durability:** SQLite keeps job state, job IDs and complete result receipts; enqueue is idempotent.
- **Claim identity:** every RUNNING job has a unique lease token; obsolete workers cannot commit their results.
- **Recovery:** an expired claim becomes eligible for one retry. After two claimed attempts, the job is marked FAILED.
- **Idempotent experimental results:** each job's separate benchmark evidence can be reused if a process stops between generating it and writing the queue receipt.

## Limitations

A lease is 60 seconds and is not renewed during execution; this is suitable only for the bundled fast fixture workload. A long-running worker could finish after its lease and its receipt would be rejected, although side effects cannot be retroactively undone. No distributed exactly-once execution is claimed. No background scheduling, approval system, real Ollama model execution, paid service or general autonomous tool use has been commissioned.

Future releases should use per-capability leases, heartbeat, bounded interruption handling, signed execution receipts and independent human approval for meaningful external effects. Keep deployment authority separate from any domain-specific execution authority.
