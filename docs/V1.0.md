# v1.0 — Verified examples used on new tasks

This is the first integrated demonstration of a **retrieve → propose → independently verify → persist** loop. It runs locally, does not execute generated code and does not require a paid service.

## Offline demonstration

```bash
python -m src.compound_intelligence.learning_loop --fixture
python -m src.compound_intelligence.learning_loop --fixture
```

The offline fixture is explicitly **simulated**. One training-style extraction example is independently checked, and only its **verified** task/output pair is retained as an exemplar. A different target notice is presented with the verified example as context. The target is independently checked against its withheld reference answer. SQLite stores exemplars and a durable run receipt; the second call recovers the same receipt without invoking a model.

To demonstrate the limit of retrieval, use `--run-id no-memory` with a fresh workspace and set `limit=0` programmatically: the offline fixture cannot complete the target without a schema example. This is deliberately scripted fixture behavior; **it does not demonstrate measured improvements in a real language model**.

## Opt-in local model

Start Ollama and pull a chosen model on your machine, then run:

```bash
python -m src.compound_intelligence.learning_loop --model YOUR_LOCAL_MODEL --run-id model-test-1
```

The model receives the current task with a maximum of three verified examples from a different task. It does *not* see the target reference answer. The model's answer has no verification authority. Any failed seed is never promoted to reusable knowledge. This proves an integration pathway only: no model is installed or commissioned by this repository.

## Controls and limitations

- Explicit execution only; no background agent, shell execution, automatic commits or repository write tokens.
- Local SQLite evidence; stable run IDs and content digests, no claim of cryptographic provenance.
- Strict bounded problem types and independent **exact-match** validators, not semantic quality evaluation or executable code tests.
- Only three prior verified examples can be retrieved, matched by task type and extraction field set. Same task ID or identical public task is never retrieved.
- Verified exemplars are **examples for a new prompt**, not online training, retained model weights, or evidence of causal improvement.
- The offline fixture supports extraction only; code-fix proposals remain static in v0.4.

A genuinely compelling real-world claim will require predeclared held-out evaluation sets, real model version attestations, baseline/assisted comparisons with multiple tasks, and repeated runs.
