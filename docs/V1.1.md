# v1.1 — Paired baseline-versus-memory evaluation

Does adding retrieved *verified* examples help a model answer a different task? This release provides a reproducible way to ask that question rather than assuming the answer.

## Offline demonstration

```bash
python -m src.compound_intelligence.ab_evaluation --fixture
python -m src.compound_intelligence.ab_evaluation --fixture
```

This **scripted fixture** requires an example to answer, so it intentionally produces a baseline `NO_RESULT` and assisted `VERIFIED`. This is a **test of A/B wiring**, not evidence that a real model improves.

## Test a local model

Start Ollama, install a model you choose, and run:

```bash
python -m src.compound_intelligence.ab_evaluation --model YOUR_LOCAL_MODEL --run-id real-001
```

The CLI independently validates seed examples before storing them. Baseline receives only the held-out task. Assisted receives the same task with up to three verified examples of the same type, excluding identical tasks. Neither receives held-out `expected` reference answers.

Per-task results report both statuses, retrieved source digests and invocation order. Aggregate counts show verified per arm, paired gains and paired losses. Run IDs protect completed receipts from duplicate inference, but a process interruption before a receipt is committed can cause repeated model calls on restart.

## Interpretation and limitations

Both arms use the same model identifier. The program alternates arm order across tasks to reduce simple invocation-order effects. Real hosted/local models can still be stochastic; repeated independent trials and fresh held-out sets are needed before a reliability claim. These data are only exact-match extraction and static patch checks; generated code is never executed. A higher assisted score on one tiny dataset does **not** establish causal memory benefit, autonomy, online learning or generalized intelligence.

All processing is explicit and bounded: at most ten seeds and ten targets per call, at most three retrieved examples. No new background job, external hosted model, repository write access, host administration or production control-plane integration is introduced.

Future work: independently curated benchmarks, version attestations, seed/target data-leak checks, baseline/assisted repeated trials, resource/cost metrics, and durable per-arm call records.
