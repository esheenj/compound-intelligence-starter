Can an AI agent prove it controls a key for a specific request? This experiment uses your browser's genuine P-256 ECDSA + SHA-256 implementation to verify a challenge signed by a fresh disposable key. It never grants an agent access or proves who enrolled that key.

Explanation

A valid signature means access to the private key corresponding to a locally generated public key. Enrollment identity is not independently verified.

3. Understand the security boundary

Public/private key operations here are real, but the browser is playing both issuer and signer for demonstration. It cannot certify a business, person or agent, or authorize tool/API actions. Replay state only lasts for this browser session. The separate Node.js verifier includes a durable, exclusive-file nonce ledger with restart and concurrency tests.

Actual deployments require independently governed key enrollment, secure server-side challenge issuance, authenticated transport, expiry, revocation, durable replay protection across nodes, audit trails and separately authorized actions. The demo never connects to a real agent, exchanges data with a server, stores secrets or runs trading code.
